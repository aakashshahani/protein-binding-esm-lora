# protein-binding-esm-lora

Per-residue prediction of **protein small-molecule (ligand) binding sites**, modernized
around protein language models (ESM-2), benchmarked against published methods, and served
behind a FastAPI endpoint.

> **Honesty note.** This README reports **only measured numbers**. Rows for models in this
> repo are marked _pending_ until a real training run fills them in from
> `outputs/<run>/test_metrics.json`. External methods are shown either as **reproduced**
> (we ran their tool on our split) or **published** (transcribed from the paper, clearly
> labeled, not reproduced). Nothing here is hand-tuned to look good.

[![CI](https://github.com/aakashshahani/protein-binding-esm-lora/actions/workflows/ci.yml/badge.svg)](https://github.com/aakashshahani/protein-binding-esm-lora/actions/workflows/ci.yml)

## What this is

Given a protein sequence, predict for **each residue** the probability that it participates
in binding a small-molecule ligand. Binding residues are rare (a few percent of positions),
so this is a heavily imbalanced per-residue classification problem.

**Modeling ladder (the story):**

| Rung | Model | Trains |
| --- | --- | --- |
| (a) | **BiLSTM** over cached ESM-2 embeddings (+ optional physicochemical features) | classical baseline |
| (b) | **Frozen ESM-2 + token head** (MLP) — mirrors the CLAPE-SMB setup | cheap, fair comparison |
| (c) | **ESM-2 fine-tuned with LoRA/PEFT** — 150M locally, 650M on Colab | modern approach |

Class imbalance is handled with **focal loss** (default) or class-weighted BCE.

## Data

- **Benchmark: UniProtSMB**, via [CLAPE-SMB](https://github.com/JueWangTHU/CLAPE-SMB)
  (`Raw_data/UniProtSMB/`). Snapshot of UniProtKB reviewed proteins with 3D structures +
  small-molecule binding sites, **dated 2024-04-17** (paper:
  [J. Cheminformatics 2024](https://doi.org/10.1186/s13321-024-00920-2)).
- We **reuse CLAPE-SMB's published train/valid/test split** so our test numbers are directly
  comparable to their paper. The exact repo commit + a SHA-256 of every file is recorded in
  `data/DATA_RELEASE.json` at download time.
- Records are 3-line format: `>ID` / sequence / per-residue `0/1` label string.
- **Anti-leakage:** independently of the published split, we cluster all sequences with
  **MMseqs2 at 30% identity** and (1) audit train↔test homology, (2) build GroupKFold CV
  folds keyed by cluster so homologs never span folds. See `scripts/cluster_split.py`.
- **Cross-dataset generalization (stretch):** BioLiP2 is wired in as an _external_ test set
  only — never mixed into the comparable numbers.

Large data and embeddings are **gitignored** and regenerated by scripts (see below).

## Results

**Primary metric: AUPRC** (average precision) — the right call under heavy imbalance. We also
report AUROC, F1, precision, recall, MCC at the validation-selected threshold.

Numbers below are measured on the held-out **UniProtSMB test split** (496 proteins,
205,848 residues, 2.70% binding) at the validation-selected threshold. Regenerate with
`scripts/evaluate.py` (embedding models) / `scripts/evaluate_lora.py` (LoRA); per-run
tables are written to `outputs/<run>/benchmark.md`.

**Dataset: UniProtSMB test** — snapshot 2024-04-17, CLAPE-SMB commit `998b378`

| method | source | AUPRC | AUROC | F1 | precision | recall | MCC |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **BiLSTM** (ESM-2 650M emb + physchem) | ours | **0.654** | 0.958 | 0.623 | 0.630 | 0.616 | **0.613** |
| LoRA ESM-2 150M (local) | ours | 0.642 | 0.948 | 0.611 | 0.655 | 0.572 | 0.602 |
| Frozen ESM-2 650M + head | ours | 0.621 | 0.945 | 0.585 | 0.636 | 0.541 | 0.576 |
| LoRA ESM-2 650M (Colab) | ours | _pending_ | _pending_ | _pending_ | _pending_ | _pending_ | _pending_ |
| CLAPE-SMB | **published** | — | — | — | — | — | **0.699** |

**Honest reading of these results:**
- The **BiLSTM over 650M embeddings is our strongest** model (AUPRC 0.654, MCC 0.613) — it
  combines the largest encoder's features with sequential context and physicochemical
  signals. LoRA-**150M** (0.642 / 0.602) is close behind despite fine-tuning a 4×-smaller
  encoder; frozen-head (0.621 / 0.576) is last, as expected for a context-free per-residue MLP.
- All three trail the published **CLAPE-SMB MCC 0.699**. That gap is expected: CLAPE-SMB
  fine-tunes on the 650M encoder with contrastive pre-training, whereas our LoRA run here is
  on 150M and our frozen/BiLSTM rungs don't fine-tune the encoder. The **650M LoRA (Colab)**
  is the run most likely to close it — it's the pending flagship.
- **LoRA-150M was stopped at its best validation epoch (epoch 5).** On the 4 GB GTX 1650 each
  epoch took ~2.6 h and validation AUPRC had already peaked (epoch 6 regressed), so continuing
  wasn't worth the wall-clock. This is an honest engineering tradeoff, not a tuned result.

> CLAPE-SMB MCC 0.699 is transcribed from the paper (UniProtSMB test set) and is **not
> reproduced** here. SCRIBER and a 2024-era method (GPSite / GraphBind) will be added as
> **reproduced** rows where their released tools run on our split, otherwise as clearly
> labeled published rows.

## Reproduce

```bash
# 0. Environment (Windows/Linux/macOS, Python >=3.10)
python -m venv .venv && . .venv/Scripts/activate      # PowerShell: .venv\Scripts\Activate.ps1
# For NVIDIA GPU (e.g. GTX 1650): CUDA torch first
pip install -r requirements-gpu.txt --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt && pip install -e .

# 1. Data: download the pinned UniProtSMB split + write data card / release manifest
python scripts/download_data.py --config configs/data.yaml
python scripts/build_dataset.py  --config configs/data.yaml

# 2. Anti-leakage: MMseqs2 30% clustering + leakage audit + CV folds (needs Docker or mmseqs)
python scripts/cluster_split.py  --config configs/data.yaml

# 3. Features: cache ESM-2 per-residue embeddings (slow step; resumable)
python scripts/extract_embeddings.py --config configs/bilstm.yaml --splits train valid test

# 4. Train the ladder (logs to W&B, offline by default)
python scripts/train.py --config configs/bilstm.yaml
python scripts/train.py --config configs/frozen_head.yaml
python scripts/train.py --config configs/lora.yaml --track local     # 150M on 4 GB GPU
#   650M LoRA flagship: notebooks/colab_lora.ipynb on a free Colab T4

# 5. Evaluate on the held-out test set -> writes test_metrics.json + benchmark.md
python scripts/evaluate.py --run outputs/bilstm_esm2_t33_650M_UR50D
python scripts/evaluate.py --run outputs/frozen_head_esm2_t33_650M_UR50D
python scripts/evaluate_lora.py --run outputs/lora_esm2_t30_150M_UR50D_local \
    --model-id facebook/esm2_t30_150M_UR50D --track local
```

Seeds are fixed (`configs/*.yaml`, `pbsite.utils.set_seed`). W&B defaults to **offline**
(`WANDB_MODE=offline`); `wandb sync` later to upload.

## Serving

```bash
# needs a trained model dir with model.pt + meta.json
export PBSITE_MODEL_DIR=outputs/frozen_head_esm2_t33_650M_UR50D
uvicorn pbsite.serve.api:app --port 8000
# POST a sequence -> per-residue binding probabilities
curl -s localhost:8000/predict -H 'content-type: application/json' \
     -d '{"sequence":"MKTAYIAKQR"}'
```

`GET /health` works even before any model is trained (returns `model_loaded: false`); the
`/predict` route returns a clear 503 until `PBSITE_MODEL_DIR` points at a trained model.

**Docker:**

```bash
docker build -f docker/Dockerfile -t pbsite-serve .
docker run -p 8000:8000 -v $PWD/outputs/frozen_head_esm2_t33_650M_UR50D:/models pbsite-serve
```

## Hardware & compute notes

Developed against an **NVIDIA GTX 1650 (4 GB)**. On 4 GB:

- ESM-2 **650M embedding extraction** fits (fp16, batch 1, long sequences windowed).
- BiLSTM and frozen-head training run comfortably on cached embeddings.
- **LoRA fine-tuning of 650M does _not_ fit for training** — so the local LoRA rung uses
  ESM-2 **150M**, and the **650M** flagship runs on a free Colab **T4 (16 GB)**
  (`notebooks/colab_lora.ipynb`). The README labels every row by the hardware that produced it.
